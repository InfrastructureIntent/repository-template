## Process notes

- `CHANGELOG.md` records curated notable changes as work lands; it is not generated from git history.
- `TODO.md` is not a second backlog and does not authorize implementation.
- `RELEASE_NOTES.md` evolves during a milestone and may seed the GitHub Release description at closeout.
- Release links/tags must not be referenced as existing until they actually exist.
- Package validation and artifact publication remain separate release concerns.
- Agent/Copilot guidance is advisory to implementation but normative for repository process: agents must not silently diverge from accepted architecture or dismiss review findings without rationale.
- New public contracts or extensibility points should be driven by concrete Engine/consumer pressure rather than speculative abstraction.
- Template standards that become normative after an earlier workflow was written must be carried back into Architecture Check so generated repositories cannot silently drift from the documented template contract.
