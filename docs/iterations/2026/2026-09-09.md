## Reusable findings fed back into the template

The Engine pressure test exposed the following reusable test-baseline gaps:

1. `global.json` selects `Microsoft.Testing.Platform`, so generated test projects must use an MTP-compatible framework baseline rather than an unspecified/legacy runner.
2. `Microsoft.NET.Test.Sdk`, `xunit.v3`, and `xunit.runner.visualstudio` versions should be centrally managed by the template baseline.
3. A newly initialized test project must contain at least one real test. Microsoft.Testing.Platform treats a zero-tests run as non-success, so an empty test project does not prove the CI pipeline.
4. Test code must still comply with the repository analyzer baseline; the initial smoke-test method name with underscores triggered CA1707 because warnings are treated as errors.
5. Bootstrap-only production code must not accidentally establish public API surface. Engine's assembly marker was made `internal`; this is an Engine-specific implementation lesson rather than a generic template requirement.

## Template changes under issue #6

- Added central versions for `Microsoft.NET.Test.Sdk` 18.9.0, `xunit.v3` 4.0.0, and `xunit.runner.visualstudio` 4.0.0.
- Updated the typical test-project example to use the proven xUnit v3/Microsoft.Testing.Platform-compatible baseline.
- Updated generated-repository guidance to require at least one real test when initializing a test project.
- Strengthened Architecture Check so generated test projects must declare `IsTestProject=true`, must not reference Xml2Doc, and must reference `Microsoft.NET.Test.Sdk` plus `xunit.v3`.
- Updated `CHANGELOG.md` to record the pressure-test-driven baseline changes.
