# Contributing

InfrastructureIntent is establishing its contributor-rights model before accepting external code contributions.

Until that contributor agreement is finalized, external pull requests should not be submitted for incorporation into InfrastructureIntent-owned repositories. Issues and discussions may be used for feedback, design questions, bug reports, and proposed improvements.

Repository maintainers may still use this template for InfrastructureIntent-owned work.

## InfrastructureIntent-owned implementation workflow

For work accepted into an InfrastructureIntent-owned repository:

1. establish or select the milestone representing the intended release/scope boundary;
2. create or select a bounded GitHub issue and assign it to that milestone before implementation begins;
3. implement the issue on a focused branch;
4. update tests, generated/public documentation, changelog, release notes, and the repository-local iteration log when applicable;
5. open a pull request that links the governing issue and milestone and records validation/compatibility evidence;
6. action or explicitly disposition review findings before merge.

GitHub Issues and Milestones are authoritative for planned work. `TODO.md` is an orientation aid and does not by itself authorize implementation.

Architecture and contributor-rights policy remain canonical in `InfrastructureIntent/documentation`. If implementation pressure conflicts with accepted architecture, propose the architecture/documentation change rather than silently diverging in code.

When external contributions open, contributor requirements will be defined canonically in `InfrastructureIntent/documentation` and reflected here.
